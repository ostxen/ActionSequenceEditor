## 1. 目标、范围与授权

目标：完善 ActionEditor 通用编辑平台，将 Combat 整理为第一套完整业务扩展。新工作台原生使用 UI Toolkit，自定义二维时间轴；Scene Handles/EditorTool 与三维预览独立。

- 复用 Combat 已有战斗事件运行时、预览经验、挂点、HitBox 和示例，不从零建设万能战斗引擎。
- 分离编辑数据、工作区、执行实例和预览会话；核心不得依赖 Combat，Runtime 不得依赖 Editor。
- 不承担旧窗口、旧 API 或旧格式兼容要求；但这不授权覆盖或删除用户原始资产。保留原样参照样本，旧代码移除单独列清单确认。
- 第一版先打通单技能、单主要动画的真实闭环，再完善复杂业务和第二业务验证。
- 不建设节点图、任意停靠系统、完整战斗框架或网络栈，不自动升级 Unity/Pipeline/CLI。
- 2026-11-09 用户明确授权初始化 Git、配置常规忽略并排除 Combat，随后选择依序实施 A00–B06、Combat 专属验收暂缓。每项验收后单独本地提交，远程地址后补，本轮不推送。
- 不修改 Combat 源码及原始资产；A00 的 Combat 样本播放/预览/中断基线及 A04 的 Combat 反向依赖整理按用户选择暂缓，不作为 ActionEditor 已验收的内容。
- 上述范围不包含删除原始资产、包/设置变更、平台切换、实际构建、公开发布，或绕过 Unity 写入的 preview/真实确认/approve/apply 流程。

2026-11-10 当前约束覆盖上面的历史“无旧窗口/API/格式兼容要求”：两个现有 UI 入口、现有布局、正常操作习惯和 JSON 内容必须保留；内部 API 可随调用者渐进迁移。未确认的旧缺陷不作为兼容目标，必须先复现再明确列为行为修正。当前只有一个共用文档/选择/播放头，不引入多文档模式。最新夜间授权：人工差异汇总次日确认；缩放步长采用新版，其余默认保留原版正常习惯，无法安全决定的行为保持差异并记录。按顺序执行，逐项工程验收后中文本地提交（含ActionEditor专属文档），不追踪Combat或用户未跟踪JSON/个人配置、不推送。不把授权理解为可以伪造人工验收或放松数据安全门禁。

## 2. 重命名、重新打开后的恢复步骤

1. 以新打开的 Unity 工程根目录为准，读取 `AGENTS.md`、本文件及架构文档，不使用上一会话的绝对路径。
2. ActionEditor 当前唯一实现源在 `Assets/ActionEditor/`；Combat 在 `Assets/CombatEditor/`。不要返回外部同名 ActionEditor 工程改代码，也不按工程显示名称修改这些模块名。
3. 检查现有更改和任务证据。有 Git 则看状态/差异；无 Git 仍保留用户文件，不自动初始化仓库。检查新位置是否出现更具体的 Agent 规则。
4. 核实 `ProjectSettings/ProjectVersion.txt` 与实际程序集、资源、解决方案。重命名后如生成的解决方案过期，使用 Unity 重新生成，不手改 `.sln`/`.csproj`，不假定解决方案仍叫旧工程名。
5. 涉及真实 Unity 状态时先读 `.codex/skills/unity-cli/SKILL.md`，运行 `python .codex/scripts/workflow.py doctor`；确认唯一 Editor/PID 指向新路径。不要用仍打开的旧工程或旧 Player 兜底。
6. 旧路径生成的预览/审批不可沿用；需要写入时在新路径重新预览、展示范围、取得真实确认和审批。不要复制连接描述符或读取鉴权内容。
7. 根据“下一任务”和用户指示继续。上一任务为 `implementing`/`validating` 时先确认实际落地程度，不能直接重跑有副作用的步骤；为 `blocked` 时先处理阻塞。
8. 完成一个任务后更新本文件的状态、证据、风险与下一任务。当前已授权串行推进 A00–B06；涉及新的资产写入、破坏性操作或必要取舍时仍须停下确认。

## 4.1 当前重构任务 RF01–RF15（2026-11-10）

### 4.1.1 不可退化的边界

- **不同绘制、同一规则与数据**：IMGUI 保留 GUILayout/Event 适配，Toolkit 保留原生 VisualElement/Painter2D/指针捕获；业务规则、候选计算、命令、属性语义、存储共用，不用 IMGUIContainer 包装旧窗口。
- **不改版**：保留播放区、文档栏、标尺、轨道头、时间轴、底部范围、独立 Inspector 的位置与层级；保留图标、文字顺序、颜色含义、提示、辅助线和操作反馈。像素差异或原生控件限制要列明，不以新架构为理由自行简化。
- **不换操作**：鼠标按钮、修饰键、快捷键作用域、选择规则、拖动起始阈值、命中优先级、吸附临时绕过、缩放锚点和取消规则均先取基线。不能为了共用控制器静默改成另一套习惯。
- **不改数据合同**：保留 Asset/Group/Track/Clip、FullSerializer JSON、现有业务 Attribute 和用户数据；不顺便迁移到 `.asset`、稳定 ID 或 double 秒。继续保持严格保存读回、磁盘版本保护和浮点精度修复。
- **不擅改状态共享范围**：当前文档/选择/播放头共用；指针捕获和悬停属于各视图。现有视域/折叠等字段先通过适配访问，RF01 记录实际共享行为，不因“工作区独立”抽象而立即改变两窗联动或保存格式。
- **不是框架工程**：不引入 DI/MVVM/通用总线，不拆空程序集。先迁移一个真实调用入口，验证后再移其他调用者；App 仅作过渡转发，不变成第二份状态源。
- 不修改 Combat、包/设置、个人配置或既有用户 JSON；持久验证仅用获授权的隔离样本。删除旧模块、实际构建和外部写入仍需单独确认。

- 验收：正常布局与交互有可重放参照；确定一份非 Combat 点/区间样例及隔离副本策略；建立相同状态重放路径，并记录代表性和最大实际文档的首开/编辑/播放测量方法。不用现有107项通过宣称新矩阵已覆盖。

**RF02｜六项源码候选复现与缺陷处置**

- 逐项复现：非 JSON TextAsset 被选中、多选拖过零点间距变化、null 集合无法展开/创建首项、折叠片段仍参与命中、拉伸磁吸参考未刷新、中键区域外释放后残留平移。
- 每项记录起始状态、触发事件、独立预期与失败证据；确认缺陷后最小修复并重放同场景，区分正常行为保留与刻意纠错。涉及第三方原码先查可用上游修复，不能访问则明列。
- 验收：每项都有“已复现且修复并验证 / 未复现及范围 / 阻塞”结论。无法证实的不强行修复；阻塞且影响后续验收时不跳过进入对应迁移。不把尚未实现能力默认为现有行为。

**RF03｜应用上下文、状态所有权与窗口适配**

- 从 App 提取一个当前共用上下文，明确文档会话、选择、剪贴板、播放服务和每窗视图适配的归属；App 暂作无重复状态的转发入口。

- 验收：双窗口打开顺序、反复重建、关闭重开、切换文档、重复订阅/释放都正确；业务服务不依赖具体 EditorWindow 或 GUI 事件。

**RF04｜编辑事务令牌与取消生命周期**

- 明确 Begin/Update/Commit/Cancel 与发起者令牌，保留嵌套命令归外层事务；UI 不再凭任意 MouseUp 或绘制事件结束共用会话编辑。
- 验收：一手势一个 Undo；无变化不增加空步骤；异常/局部失败回滚；Esc、失焦、捕获丢失、区域外释放、窗口关闭均按基线结束。A窗关闭或失焦不能误取消B窗拥有的事务；全局放弃则按明确策略回退整个共用文档。重复提交/取消幂等，Undo/Redo/脏标记/选择正确。

**RF05｜会话、编解码与存储边界**

- 在现有存储上提取必要的 codec/store 适配，JsonDocumentSession保留基线与编辑会话；Unity导入留在边界，复用ReliableFileCommit，不增加第二套正式存储。
- 验收：新建、打开失败不切换、保存/另存、放弃、恢复快照、自动保存、严格浮点往返、文件占用、外部修改保护及保存后Undo/Redo通过真实入口；失败不损坏原字节。持久样本需走项目授权流程，不能用内存测试代替磁盘验收。

**RF06｜类型目录、能力与扩展解析**

- 缓存解释现有名称/分类/颜色/Attachable/Unique；显式表达点/区间、伸缩与渐入渐出能力；动态锁定/停用不混进类型能力，重叠规则接收候选及邻居。

**RF07｜创建及结构编辑命令归一**

**RF08｜可见布局、坐标与命中归一**
