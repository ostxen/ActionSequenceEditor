## 1. 目标、范围与授权

目标：完善 ActionEditor 通用编辑平台，将 Combat 整理为第一套完整业务扩展。新工作台原生使用 UI Toolkit，自定义二维时间轴；Scene Handles/EditorTool 与三维预览独立。

- 复用 Combat 已有战斗事件运行时、预览经验、挂点、HitBox 和示例，不从零建设万能战斗引擎。
- 分离编辑数据、工作区、执行实例和预览会话；核心不得依赖 Combat，Runtime 不得依赖 Editor。
- 不承担旧窗口、旧 API 或旧格式兼容要求；但这不授权覆盖或删除用户原始资产。保留原样参照样本，旧代码移除单独列清单确认。
- 第一版先打通单技能、单主要动画的真实闭环，再完善复杂业务和第二业务验证。
- 不建设节点图、任意停靠系统、完整战斗框架或网络栈，不自动升级 Unity/Pipeline/CLI。
- 2026-11-09 用户明确授权初始化 Git、配置常规忽略并排除 Combat，随后选择依序实施 A00–B06、Combat 专属验收暂缓。每项验收后单独本地提交，远程地址后补，本轮不推送。
- 不修改 Combat 源码及原始资产；A00 的 Combat 样本播放/预览/中断基线及 A04 的 Combat 反向依赖整理按用户选择暂缓，不作为 ActionEditor 已验收的内容。
- 上述范围不包含删除原始资产、包/设置变更、平台切换、实际构建、公开发布，或绕过 Unity 写入的 preview/真实确认/approve/apply 流程。

## 2. 重命名、重新打开后的恢复步骤

1. 以新打开的 Unity 工程根目录为准，读取 `AGENTS.md`、本文件及架构文档，不使用上一会话的绝对路径。
2. ActionEditor 当前唯一实现源在 `Assets/ActionEditor/`；Combat 在 `Assets/CombatEditor/`。不要返回外部同名 ActionEditor 工程改代码，也不按工程显示名称修改这些模块名。
3. 检查现有更改和任务证据。有 Git 则看状态/差异；无 Git 仍保留用户文件，不自动初始化仓库。检查新位置是否出现更具体的 Agent 规则。
4. 核实 `ProjectSettings/ProjectVersion.txt` 与实际程序集、资源、解决方案。重命名后如生成的解决方案过期，使用 Unity 重新生成，不手改 `.sln`/`.csproj`，不假定解决方案仍叫旧工程名。
5. 涉及真实 Unity 状态时先读 `.codex/skills/unity-cli/SKILL.md`，运行 `python .codex/scripts/workflow.py doctor`；确认唯一 Editor/PID 指向新路径。不要用仍打开的旧工程或旧 Player 兜底。
6. 旧路径生成的预览/审批不可沿用；需要写入时在新路径重新预览、展示范围、取得真实确认和审批。不要复制连接描述符或读取鉴权内容。
7. 根据“下一任务”和用户指示继续。上一任务为 `implementing`/`validating` 时先确认实际落地程度，不能直接重跑有副作用的步骤；为 `blocked` 时先处理阻塞。
8. 完成一个任务后更新本文件的状态、证据、风险与下一任务，再停止等待用户安排。

首次执行背景：计划编写时 Unity 为 2022.3.62f3，工程没有 Git 仓库。此处是历史记录，不保证重开后的环境相同。既有工作流完整文档结构检查曾因缺少 PyYAML、markdown-it-py 阻塞，A00 应重新核实，不自动安装。

## 3. 执行规则和完成定义

### 3.1 任务状态

`planned` → `implementing` → `validating` → `complete`；无法继续时为 `blocked`，记录原因。只有实现与该任务必需验证均通过才勾选。允许尚未覆盖的范围必须明列，不能写成“全部通过”。`F01` 默认为 `deferred`。

每次执行：重读相关源码 → 确认输入与授权 → 实施本任务 → 运行对应检查 → 记录结果与下一步。下表是逻辑依赖，不授权并行修改；默认串行推进。

### 3.2 通用验收门槛

- 使用任务指定的真实入口、默认配置和原始样本验证，不仅测新写的辅助函数。
- 先将静态发现的问题复现为测试或可重复场景，再检查修复后的同一场景。待替换 UI 不先完整修复一遍，保留行为回归要求。
- 修复第三方来源代码前检查可获得的上游修复及许可，优先最小移植；访问受阻则记录，不假装已核查，不自动升级。
- 新增测试程序集和测试身份需在记录中写清，发现用例后再按真实筛选器及模式运行。不用无关包测试、零用例、跳过或旧结果代替覆盖。
- C# 变更检查真实生成项目的源码覆盖和编译；Editor 编译与真实 Player Build 分别记录，后者按明确授权执行。
- UI 交互、Scene 工具和视觉验收保留可复现操作及证据；截图不等于自动验收。工作流暂不支持所需操作时先实现并验证审核契约或请求人工步骤，不绕过授权。
- 改造完成后目标窗口不能以 IMGUIContainer 包裹旧窗口充当原生 UI Toolkit 成果。Handles 不属于这一限制。
- 每个任务结束，设计决策有变化时同步架构文档；单纯进度只更新本文件。

## 5. 分项实施与验收

### A00｜重命名后环境、源码和行为基线

- 输入：重开后的真实工程、当前两套源码、架构文档第 12～14 节与现有示例。
- 工作：核实目录、依赖、版本、现有更改和 Editor 连接；建立本次改造相关测试入口；选定一个已有攻击样本，记录原始参数、播放、预览与中断表现。核查保留模块可获得的上游修复。列明当前编译错误与阻塞，不把既有错误归因于后续改造。
- 交付：在执行记录中写入可重复基线、样本相对路径、真实测试身份、环境限制及问题归属；只建立有用的小型回归测试骨架，不虚构通过用例。
- 验收：新根目录定位正确；核心场景可重复观察。不能运行时保留明确阻塞与待复现列表，本任务不假报完成。

### A01｜编辑数据与持久化方案验证、定案

- 输入：现有普通对象图、FullSerializer 保存路径、Combat 子资产与引用需求。
- 工作：做最小技术验证，对比 Unity 原生资产/多态数据方案与继续 JSON 所需的编辑、Undo、引用及存储成本；以实际创建、编辑、保存、关闭重开和撤销验证选型，不一开始迁移全部资产。
- 交付：确定一种正式编辑资产格式及所有权、引用、ID、版本和保存方式，明确适用的多态存储手段；把决定写入记录并同步架构文档。涉及持久资产创建先确认范围。
- 验收：选定方案保留不同事件的时间、参数和 Unity 资源引用；Undo/Redo 实测可行；不将 SerializedObject 强套到任意普通 C# 对象。不需要兼容旧格式，但原始样本不被覆盖。

### A02｜时间、身份、顺序和业务扩展契约定案

- 输入：A01 结果、现有事件类型与最小攻击样本。
- 工作：明确平台公共坐标和 Combat 逻辑时间、采样帧率转换；定案点事件跨越、区间边界、0/结束点、同刻排序、循环、跳转与中断规则；定义稳定文档/事件 ID、复制时 ID 策略、逻辑/表现分类、重叠策略与注册冲突处理。
- 交付：具体类型/接口草案和带明确预期的时间真值表。将尚未决定的问题在这里解决，不能带着影响数据格式的歧义进入 A04；需要用户取舍时停下确认。
- 验收：真值表覆盖短事件、一次跨多个事件/循环、同刻事件和停止/取消区别；ID 不依赖 GetInstanceID；时钟不强制绑定 Animator，不承诺整数 Tick 自动确定性。

### A03｜保留路径的数据安全修复与回归

- 输入：A00 复现与 A01 格式决定；仅修仍被使用的保存路径。
- 工作：先验证序列化失败、损坏数据、文件不可写、打开失败后文档目标不一致、自动保存 60/120 秒等问题；修复错误传播、成功后切换和可靠提交。若旧存储即将完全替换，用新存储回归覆盖，明确旧危险入口的禁用或隔离方式，不维护两套正式存储。
- 交付：最小修复或替代存储测试，失败注入与原始文件保护证据。
- 验收：失败不会清空或覆盖最后有效数据，打开失败不发生旧内容写入新文件；自动保存按总时长/单调时间运行。删除、覆盖操作只使用经确认的隔离测试样本。

### A04｜数据基础和 Runtime/Editor 依赖整理

- 工作：按 A01/A02 建立最小数据模型、稳定 ID 与扩展边界；修正必要的 asmdef 和 Editor 引用，拆除 Combat Runtime 对预览类型的反向依赖。程序集按职责和实际规模划分，不为凑模块图拆空程序集。
- 交付：可被 Runtime 消费的数据层、明确依赖图及时间/ID 基础测试。
- 验收：核心无 Combat 类型判断，Runtime 源码无非条件 Editor 依赖；Editor 编译及相应测试通过。源码检查不能代替最终实际 Player Build，后者保留 E02 门禁。

### A05｜文档会话、工作区与可靠存储

- 工作：建立独立 DocumentSession、脏标记、成功后切换、可靠保存与关闭流程；缩放、滚动、折叠、分栏移出执行定义，文档状态不依赖静态全局 App。
- 交付：加载/保存服务、工作区状态和会话释放实现，测试文件及故障用例。
- 验收：A/B 文档切换、失败切换、重复打开/关闭、保存后重开、异常恢复正确；调整视图不改变业务内容；事件参数和资源引用往返一致。

### B01｜编辑命令、事务和 Undo/Redo

- 工作：统一新增、删除、移动、调整长度、复制、重排、批量属性修改；一次拖动一个事务，候选状态与提交分离，子对象和引用纳入同一撤销边界。
- 交付：可脱离绘制测试的命令与校验层，复制 ID 和完整参数规则。
- 验收：提交/取消/Undo/Redo 的数据、选择、脏标记一致；复制不丢时间和参数、不共享执行状态；连续重复操作、局部失败和跨文档操作不会污染原文档。

### B02｜原生 UI Toolkit 工作台与文档切换

- 工作：实现工具栏、资源/技能库列表、可调整分栏、时间轴容器、属性区及问题区；接入会话，不嵌入旧 Combat 窗口，不自研任意停靠系统。
- 交付：能打开/切换/保存文档的原生 EditorWindow 与视图生命周期。
- 验收：重建视觉树、关闭重开、重复切换不累积注册/回调；分栏与窗口尺寸变化正确；多个窗口/文档不因全局查找串状态。

### B03｜时间轴绘制、坐标和命中检测

- 工作：实现刻度、轨道、点事件、区间、播放头及可见区域裁剪；分离时间/像素变换、绘制与命中算法，避免每刻度独立元素或播放时整树重建。
- 交付：自定义 VisualElement 时间轴及坐标/命中测试。
- 验收：滚动和不同缩放下绘制与命中一致；负向拖动区域、0/末端、短事件及高密度数据可用；单纯绘制/重绘不改变资产或脏标记。

### B04｜选择、拖动、缩放、吸附与取消

- 工作：接入 B01 命令，实现单选、多选、框选、平移、时间缩放、移动、区间伸缩、吸附和锁定；处理 PointerCaptureOut、失焦、Esc、拖出区域与面板移除。
- 交付：统一交互控制器、明确的手势结束/取消规则及测试步骤。
- 验收：每次手势只提交一次；无按下不会拖动，捕获丢失后无残留；非法重叠按业务策略反馈；撤销恢复完整初态，锁定对象不被批量操作误改。

### B05｜业务注册、原生属性编辑与校验反馈

- 工作：建立类型/工厂/视图/属性/校验/预览/导出注册接口及冲突诊断；实现原生属性面板、集合/空值/基础类型、多选和错误定位，所有修改进入事务。
- 交付：平台示例类型、业务扩展入口与问题列表联动。
- 验收：新增示例类型无需修改核心分支；注册冲突可诊断；属性编辑、时间轴、Undo 和保存同步；未知类型或不合法引用不静默丢失数据。

### B06｜通用平台最小闭环阶段验收

- 工作：用平台示例验证创建→编辑→取消/撤销→重做→保存→关闭→重开的完整链路，覆盖输入异常与历史保存缺陷。
- 交付：阶段测试报告、实际交互证据和未覆盖范围。
- 验收：基础点事件与区间功能闭环；绘制只读，视图状态与定义分离；原生 UI 不依赖旧反射 IMGUI Inspector。未通过先修复，不开始扩大 Combat 接入。

### C01｜Combat 定义映射与确定性数据构建

- 工作：区分角色技能库与文档内部 Group；定义 Combat 数据扩展与角色挂点引用，将编辑定义校验、稳定排序、时间转换、资源解析为运行定义。
- 交付：首个攻击样本的新格式副本和构建/导出入口，明确内容版本与逻辑/表现分类。
- 验收：导出后重载逐字段比较业务内容；相同输入得到稳定事件顺序和内容标识；运行定义不含工作区、窗口和预览对象。不要求为旧格式做通用兼容器。

### C02｜Combat 播放实例与最小运行时接入

- 工作：保留 Animator 本地驱动入口并整理为可替换时间来源；建立独立技能实例、角色上下文和事件状态，优先复用现有 Start/Update/End 效果实现。
- 交付：新运行定义到已有业务执行能力的最小链路；定义正常结束/停止/取消及清理责任。
- 验收：选定攻击动画可驱动独立实例；同动画不同技能不能再以 Clip ID 混合事件；中断和异常清理一次且不漏结束。先做可靠最小链路，不先造完整技能系统。

### C03｜预览会话、动画求值和资源所有权

- 工作：实测并确定隔离场景/角色副本策略与 Scene 工具配合方式，避免运行副本全部游戏脚本；按动画姿势→根运动/挂点→附属效果顺序求值，支持重建与跳转。
- 交付：PreviewSession、统一角色/挂点/临时资源上下文和释放服务。
- 验收：重复创建销毁、切资产/角色、结构修改后求值不串状态；倒拖和跳转符合定义；不执行真实伤害、资源消耗等副作用，不用全局找窗口或对象名称定位资源。

### C04｜音效、挂点特效、HitBox、连招窗口接入

- 工作：将一个音效点事件、一个挂点特效、一个 HitBox 区间和一个连招窗口接入注册、属性、校验、预览与运行构建，复用 Combat 效果而非机械搬旧 UI。
- 交付：具备全部最小业务元素的单攻击技能。
- 验收：各事件可创建、复制、编辑、撤销、保存、重开；运行时与预览各自遵守时间规则，音效不能因跳转无条件重复；连招查询由业务接口提供，不扩建状态机图。

### C05｜挂点与 HitBox Scene 编辑工具

- 工作：整理 Handles/EditorTool，将选中事件、角色挂点和 Scene 目标与会话绑定；位置、旋转、碰撞盒编辑进入同一事务。
- 交付：Scene 选择、可视化、拖柄和原生属性面板联动。
- 验收：对象缩放/旋转及坐标变换正确，Undo/Redo 一致；工具退出、切文档、切角色、删事件后无残留控制；原始角色和资产不被预览静默改写。

### C06｜单攻击技能端到端阶段验收

- 工作：走通创建→编辑→撤销→保存→重开→预览→游戏运行→中断清理，以 A00 的真实示例和参数为独立参照，并列明刻意修正的旧缺陷。
- 交付：EditMode/PlayMode 实际测试结果与人工交互验收、差异清单。
- 验收：动画、音效、特效、HitBox、连招窗口全部闭环；预览不产生真实战斗副作用；最小功能通过后才进入复杂事件，不以仅有 UI 或导出文件宣称完成。

### D01｜循环、过渡、多层、重入与实例隔离

- 工作：完整实现 A02 真值表，定义 Animator 源/目标片段过渡及多层策略；验证独立时钟入口、跨多循环、重复释放与多角色并发。
- 交付：时间调度与实例隔离回归套件。
- 验收：同刻排序稳定；跨帧事件不漏不重；同动画不同技能、多层、多个角色和实例中断不串状态；跳转预览与向前游戏执行按各自契约测试，不强求副作用完全相同。

### D02｜位移、变速、拖尾与不跟随特效

- 工作：接入现有复杂效果、多阶段窗口及其重叠策略；处理非跟随特效生成时刻姿势和动画速度/时间来源的关系。
- 交付：复杂技能样本及对应属性、校验、预览/执行实现。
- 验收：连续播放、随机跳转、倒拖、循环和中断分别符合预期；多个效果的累加/覆盖/混合明确，变速不形成逻辑时钟反馈错误，拖尾/特效资源可回收。

### D03｜生命周期、故障与破坏性操作回归

- 工作：覆盖关闭窗口、切资产/角色/场景、脚本重编译、进出 Play Mode、事件增删改、预览异常、保存失败和重复释放；测试授权范围内的隔离样本，不触碰原始数据。
- 交付：端到端生命周期测试矩阵、资源残留观测及故障恢复证据。
- 验收：无遗留订阅、预览对象或失效缓存；场景状态按约定恢复，失败不损坏文件；部分完成和重复操作后仍能恢复，不仅验证正常启动/关闭一次。

### D04｜首开、重载和重负载性能测量与优化

- 工作：用当前最重真实文档与记录规模的压力样本，测新进程首开/首次预览、滚动缩放拖动、播放、反复增删和会话重建；记录硬件、配置、耗时、分配和内存/对象残留。
- 交付：优化前后同路径测量与可复现数据；基于实测提出交互预算并确认，不编造既有性能门槛。
- 验收：检查峰值/最差场景而非只报平均；有明确瓶颈才优化，最终版本重新测量；连续循环无持续资源增长，不能以“换了 UI Toolkit”代替测量。

### E01｜选择并接入第二个非战斗业务

- 工作：从简单镜头序列或 Buff 表现中选一个，先用真实范围明确时间和预览需求；若选择影响用户目标则先确认，再完成数据、注册、属性、校验、预览与保存闭环。
- 交付：第二业务的可运行样本和核心变更审计。
- 验收：不复制时间轴、事务或存储；不把新业务判断散入核心，必要的通用接口调整有可解释依据及 Combat 回归；证明平台可扩展，不要求万能播放器。

### E02｜Player 边界验证、旧路径退役与交付

- 工作：明确目标平台和构建输出并取得实际构建授权；验证可运行示例 Player，不只是 Editor 编译。列出被替代窗口、输入/Inspector/预览路径及其引用，用户确认后移除或退役，保留需要的业务实现、原始参照与许可证。
- 交付：Player Build 及运行检查报告、最终目录/依赖图、业务扩展指南、已知限制和退役清单。
- 验收：目标 Player 无 Editor 依赖泄漏，关键技能示例运行正确；最终新入口原生 UI Toolkit，无两套正式编辑路径；未授权构建或删除时明确 blocked，不能标记完成。

### F01｜具体联网项目增强（deferred）

- 启动条件：用户提供具体联网项目、权威/预测/回滚目标及实施授权。在此前不实现网络协议、服务器、快照或回滚系统。
- 工作：届时先形成独立的具体需求与任务分解，复用稳定 ID、时间、分类和导出契约；定义权威 Tick、重演身份、副作用去重/撤销、版本匹配和实际模拟边界。
- 验收：以确定网络架构的真实延迟、纠正、重复事件及版本差异场景验收；固定 Tick 不作为确定性或联网完成的证明。当前计划不勾选此项。
